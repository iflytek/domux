2. 自我纠正语句保留完整上下文；英文 ASR 别名增加词边界，避免修改 satellite。
3. 统一七字段协议检查，拒绝空字段、空 gold 和未知动作。

5. 评分重新计算正确性，不信任结果文件中预计算的布尔标记。
6. 对比拒绝缺失、重复 ID、数据差异、混合版本与参数；新运行需完成状态和文件摘要。
7. 输出采用独占创建；断点恢复检查完整前缀，保护旧结果。错误记录保留，失败实验返回非零状态。
8. API 空 choices、null 内容和截断响应会记为失败。CPU 输出达到 token 上限而未遇 EOS 时记为失败。
9. 新增输出策略检查，但只产生离线 candidate/clarify/reject；execution_performed 始终为 false。
10. CI 加入数据验证、回归测试和本地模拟 HTTP 全流程测试；不放宽公开案例发布要求。

## 证据类型

- 回归测试：定向反例先失败，再修复通过。
- 本地模拟接口：真实启动 HTTP 服务并运行两条 CLI 流水线及评分，覆盖 80+80 条合成响应。
  这些完美响应由测试提供者返回，不代表模型准确率。
- 真实模型：同一固定 Domux revision、本机 Transformers CPU BF16、16 线程、greedy、128 token 上限。
  逐条证据及代码、数据、设置摘要分别保存在本目录的 outputs/environment 文件。
- 历史重算：historical_rescored_metrics.json 明确标为 legacy_rescore，保留来源局限。

## 仍然没有证明的部分

- 没有真实设备身份解析、权限、确认对话、撤销、超时恢复或设备回执；不能将 candidate 当成执行许可。
- 词法安全策略不覆盖所有同义词、否定、多设备指代与上下文歧义。
- 模型仍可能输出多余动作、错误设备或房间；格式正确不代表语义正确。
- 80 条合成数据包含重复文本，规则已经根据样本调整；新增反例不是独立统计留出集。
- 单次 CPU 运行不证明用户可接受延迟；加载前后 RSS 差不是峰值内存。
- API revision 由调用者声明，不能证明服务实际加载了对应权重。
- 恢复任务必须沿用同一软件环境；不支持同一结果文件的并发写入。
- 并行提交 c906b98 已补入 Discussion #7，本轮本地案例校验通过。未放宽发布要求；本轮没有发布或修改远端内容，网页读取失败，未独立复核远端帖子。

## 本次运行结果

- 本机完整测试：31 项全部通过；数据校验、案例校验、diff 空白检查均通过。
- 原始输入、归一化输入各 80 条真实 CPU 推理，共 160 次，运行错误均为 0。
- 新严格评分器：`2-ordered-exact-lcs-f1`。两份结果的 ID、代码、数据、设置摘要一致，完成状态和结果摘要检查通过。
- 当前工作区代码摘要与两轮运行记录相同；不是修复前的旧日志冒充新代码验证。
